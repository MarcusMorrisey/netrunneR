## Verified facts

- `lineage("nrdb")` (R/lineage.R:115) is PURE — builds a list from `.LINEAGE_REGISTRY`,
  touches no filesystem. `base_url = "https://netrunnerdb.com/api/2.0/public"`,
  `pacing = list(min_delay_s = 1, max_delay_s = 2)`. Safe to call from a Shiny session
  purely to hand `nrdb_get()` its base_url + pacing. No new registry entry needed.
- `nrdb_get(lineage, path, query)` (R/fetch-nrdb.R) returns
  `jsonlite::fromJSON(body, simplifyVector = TRUE)`. simplifyVector=TRUE means the
  deck envelope's `data` becomes a data.frame and `cards` a NAMED LIST (code -> qty),
  not a tibble. Plan must account for that shape.
- `capture_response_body()` (R/capture.R) is memory-only (resp_body_string). No disk
  write. So routing deck fetch through nrdb_get() writes nothing — persistence
  constraint satisfied structurally, not just by discipline.
- `tests/testthat/test-capture-boundary.R` static AST scan globs `R/*fetch*.R`.
  A file named `R/deck-compare.R` is NOT scanned. Splitting the network half into
  `R/fetch-deck.R` puts it under the existing gate for free.
- `compute_ice_breaker_matchups()` output columns: ice_code, breaker_code,
  cost_to_break, stealth_credits, credit_differential, source. Arranged by
  ice_code, breaker_code. Confirmed.
- `mod_matchup_explorer_server()` render logic is SUBJECT-ANCHORED: it collapses to a
  single "counterpart" column because the opened card is constant on every row.
  Deck-compare varies on BOTH axes, so the reactable column set is genuinely different.
  The shareable parts are narrower than "the table": the `display` pipeline
  (code-set filter -> title join -> sort by cost_to_break), the `na_dash` em-dash
  cell renderer (\u2014 escape, R CMD check non-ASCII), and the cost/differential/source
  colDefs. Extract those three; do NOT try to share the whole reactable.
- **BLOCKER FOUND**: `load_ice_breaker_app_data()` (R/operations.R:215) sets
  `cards <- ice_breaker_pool(cardpool_result$tables$card)` — app_data$cards holds ONLY
  ice + icebreakers. `identities` is carried separately; the full `card` table is NOT
  exposed. So the app cannot currently tell "deck code unknown to this cardpool release"
  (version skew / reprint — must be surfaced per constraint) from "code is a known card
  that simply isn't ice or a breaker" (an Agenda, an event — must be silently ignored).
  Merging those two is exactly the failure the MUST forbids. Fix: have
  load_ice_breaker_app_data() also return a minimal `all_codes` frame
  (code/title/type_code from all_cards, which it already materialises at line 251).
- App HAS a nav strip: `suite_nav_ui()` (R/mod_lane_board.R:107) with three built views
  iceBreaker / metaMaps / metaStats, driven by non-namespaced `nav_view` input, read
  only in app_server.R:140. The context.json assumption "there is no navbar" is STALE.
  It also has an `nr-suite-item-inert` "Not built yet" state for unbuilt entries.
- `output$release_info` caption convention: app_server.R:180-186, laid down in
  app_ui.R:50 OUTSIDE the swapped `main` slot. Inline style
  `font-size: 11px; color: #8a8f98; padding: 2px 12px;`.
- Modals: both existing modals share `#shiny-modal` and must REPLACE, never stack.
  Each carries a marker div (`.dc-matchup-modal`) so the delegated
  `hidden.bs.modal` handler only fires for its own. A third modal needs its own marker.
  Module must be instantiated ONCE per session against a caller-owned reactiveVal.
- Testing: testthat. `httr2::local_mocked_responses()` for fetch (see
  test-fetch-nrdb.R), `shiny::testServer()` for modules, `helper-mini-pool.R` for
  cardpool/traits/overrides fixtures, `helper-store-fixture.R` for promoted releases.
  `shinytest2` deliberately absent from renv.lock — integration tests skip by design.
- Gates: `make test` (FAIL 0) and `make docs-current` (man/ + NAMESPACE regenerated by
